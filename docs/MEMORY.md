# 你的记忆，留在你自己的地方

[返回首页](../README.md) · [Provider 接入](PROVIDERS.md) · [English protocol](../skills/adaptive-personal-ai-os/references/memory.md)

## 先使用，再按需个性化

下载智序不会自动建立档案，也不会扫描你的历史。它先使用当前会话中已有且相关的背景。需要长期连续性时，你再决定是否保存，以及保存到哪里。

**不保存：**这次不读取、不写入智序的持久档案。

**确认后保存：**先知道将记住什么、关于谁、适用范围和保存位置。

**授权低敏积累：**在约定范围内保留低敏偏好与进度；敏感信息和重要更正另行明确。

这些只是智序的协作规则，不能代替宿主原生记忆或聊天历史设置。

## 先评估现有方案

首次需要跨会话连续性时评估记忆方案，并在当前范围复用选择结果。仍需连续性且宿主、账号、范围或能力实质变化时，只复查受影响的部分。Agent 依次检查：

1. 当前 Agent 已经提供的原生记忆；
2. 用户已经安装并授权的记忆工具；
3. 当前环境是否启用、当前会话是否可调用；
4. 保存、读取、更正、删除、范围、跨会话、跨 Agent、导入导出和并发保护的实际证据。

推荐遵循四个选项：

- **A 原生记忆**：原生能力已覆盖需求时继续使用，不增加 provider。
- **B 原生记忆 + 私人档案**：只有明确需要跨 Agent，且私人档案有明确范围和版本/锁保护时使用。
- **C 已安装的成熟 provider**：只有发现明确缺口，且 provider 已安装、启用、可调用，许可证、维护状态、接口和隔离测试都清楚时使用。
- **D 暂不使用额外记忆**：没有缺口、没有权限、无法验证，或用户不想保存时使用。

安装了 Skill 或看到了文档，不等于 provider 可用。完整字段和适配器操作见 [记忆方案接入](PROVIDERS.md) 与 [provider contract](../skills/adaptive-personal-ai-os/references/provider-contract.md)。

## 最小私人档案

用户可以选择一个不属于公开仓库、也不在 Skill 安装包里的独立目录，例如 `~/ZhiXu-Private/`。只在用户要求时创建，位置要让获准使用的 Agent 明确知道，不全盘搜索。

最开始只需要 `PROFILE.md`（偏好、目标与授权范围）和 `MEMORY.md`（少量已确认记录）；学习和项目状态优先沿用现有文件。无需一上来建立十几份模板。

每条重要记忆保留：**内容、信息主体、来源、日期、适用范围、确认状态、可共享服务与复查日期**。区分使用者资料、项目资料和引用材料；临时要求不自动成为长期偏好。

## 查看、纠错、遗忘

可以用自然语言要求查看已保存的内容、更新过时记录或删除指定条目。

Agent 应先定位授权范围内的实际文件，用宿主工具读取或修改，并报告结果。没有写权限时只能提供草稿，不能说“已经记住”。不要静默覆盖另一位协作者刚写的内容。

删除当前文件中的记录，不代表旧对话、原生记忆、备份或已经进入模型上下文的内容都被删除。不得为了留痕又复制一份被要求删除的私人内容。

## 换 Agent，不等于把隐私重新公开

同一个人可以授权 Codex、Claude Code 或 DSH 读取同一份精选档案。但 **Agent 名称和模型服务商不是一回事**：更换服务或账号前，要明确哪些记录可以共享。

已有原生记忆不批量迁移。只读取当前已提供的相关背景，或用户指定的具体来源；先给候选摘要，再按授权写入，不覆盖原生文件。跨设备同步不由智序自动提供。切换 provider 时先停止旧 provider 写入，只迁移用户明确选择的记录，并核对新 provider 的读取结果。迁移不自动删除源记录；删除仍需单独明确范围并遵守宿主确认要求。

## 当前边界

本版依靠宿主的原生能力、已选 provider 和人工授权，没有独立记忆数据库、向量检索、自动权限过滤或自动同步。多 Agent 共用档案时，采用单写入者，或使用 provider/宿主已验证的版本冲突控制；没有保护就停止并行写入。

本地保存也不意味着数据永不离开设备：供云端模型阅读的内容可能进入对应服务商的上下文。不要保存密码、密钥、验证码，健康、关系、财务信息默认不长期保存。

**公开 Skill 负责方法；私人档案负责使用者自己的配置与事实。两者不能混在一起。**
