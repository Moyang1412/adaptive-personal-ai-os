# 使用示例

[返回首页](../README.md)

以下场景为独立编写的虚构示例，用于说明工作方式，不对应某位使用者的经历，也不是实测对话记录。验证范围见[验证报告](VALIDATION.md)。

标注“未发布”的流程仅在本地源码中调整，当前发布版本仍为 v0.4.0 Preview，安装副本不会自动更新。新增工作方式的依据及实际检查范围分别见[来源核验](RESEARCH-NONLEARNING-2026-10-13.md)和[行为验证](VALIDATION-NONLEARNING.md)；示例本身不证明有效性。

## 学习：直接开始，逐步了解基础（未发布）

**请求：**我想学电子表格，先把社团活动的费用按类别汇总。

**工作方式：**从提供的数据和当前操作开始，说明汇总方法。在任务需要时留一个可跳过的尝试，例如独立新增一种分类，观察是否需要提示。已经能独立完成的部分减少重复讲解；继续演示的部分保留为尚无独立证据。

**得到什么：**可用的汇总结果和下一项适量练习。助手生成的公式不算用户已掌握；用户只想看演示、拒绝尝试或回复慢，都不据此判定不会。证据不足仍可继续帮助。

## 学习：自选简短诊断（未发布）

**请求：**我准备学地图比例尺，先帮我看看应该从哪一步开始。

**工作方式：**针对单位换算和比例关系安排少量尝试，按具体表现和帮助量调整起点。如果用户想直接学，随时切换并复用已有证据，不重开一套测试。以后用独立新任务及延迟检查了解保持和迁移。

**得到什么：**有依据的学习起点，未知项继续标为未知。两种方式采用同一证据标准；学习卡和保存可选，不因未保存而中断学习。少提问本身不证明更高效，还要比较相近学习效果下的时间和负担。

## 决策：看清不同选项的取舍

**请求：**有三种活动场地方案，请按人数、费用和交通条件比较。

**工作方式：**整理已提供的信息，指出会影响判断的缺口，比较选项并给出建议及适用条件。

**得到什么：**与当前目标对应的比较结果，不把不相关的旧背景作为决策依据。

## 计划与决策：让建议适合现实条件（未发布）

**请求：**周六要布置一个虚构书展，只有一名志愿者和两小时。有自取展架和送装展架两种方案，先给可执行的安排。

**工作方式：**先用已知容量安排，明确“安全摆好必要展架并核对通道”的完成条件和下一步。核查自取所需搬运条件；若一人无法搬运，自取就不满足约束。送装是否准时是可能改变推荐的关键未知，应优先确认，而不是继续比较装饰细节。

**边界：**到货尚未确认，就给有条件的安排或缩减方案，不编造空闲人手或保证当天完成；推荐方案不等于已经预订。

## 研究：核对主张，而不只收集链接（未发布）

**请求：**一个开源工具说能让读书会签到更快，帮我判断是否值得试用。

**工作方式：**检查项目的当前实现和声明依据，分别核对签到耗时、录入错误及维护成本。如果引用的论文只测过课堂提醒，就保留它对提醒设计的启发，不把结果外推成签到效率证明。关键问题已有足够依据时停止重复搜索。

**边界：**必要时建议一次有范围的试用，并说明看什么结果；无法访问的论文写明未核验。GitHub 热度或示例演示不能替代本地试用结果。

## 任务续接：基于现状继续

**请求：**查看示例项目的进度，先只读整理下一步。

**工作方式：**读取已有状态和相关文件，区分已完成、待验证和计划中的工作。保持只读，不额外创建文件或运行会写入产物的命令。

**得到什么：**可以核对的现状摘要，以及下一步需要做什么。

**未发布补充：**把交接中的完成声明与当前文件、版本及结果证据对照。旧记录写“待改”的内容若已完成，就继续实际下一步；某个文件后续被修改时，只重新核对受影响的证据，不默认以前所有检查仍然有效。

## 复盘与沟通：先处理所求的一件事（未发布）

**请求：**虚构的绘本活动原定 40 分钟，实际用了 55 分钟；记录显示发材料用了 12 分钟。帮我找下次先改的一件事，再给搭档一段简短说明。

**工作方式：**把超时和材料发放耗时作为已报告的观察，不直接断言全部超时都由发材料造成。可以先尝试提前分装，并比较下次的发放耗时和活动总时长。再根据这些事实起草简短说明及协作请求。

**边界：**一次结果不能证明因果。草稿不是发送授权，不推断搭档动机；如果用户只希望倾听，就回应当下感受，不强制展开复盘或问卷。

## 个性化：配置属于使用者

**请求：**以后用表格比较方案，保存到我的私人配置中。

**工作方式：**在保存位置和权限明确后，用当前宿主的可用工具修改相应配置并核对结果。该偏好只用于这名使用者，其他人仍可采用不同形式。

**得到什么：**可查看、可修改的协作偏好；没有写入能力时，只提供待保存草稿。

## 更换 Agent：复用获准的进度

**请求：**在新 Agent 里继续这一项学习计划，只读取我指定的进度文件。

**工作方式：**确认实际模型服务、文件位置和授权范围，只读取本次需要的部分。不自动扫描或共享其他档案。

**得到什么：**基于既有进度的下一项任务，同时保留原有隐私边界。

## 记忆方案：先检查，再选择

**请求：**我想让两个 Agent 继续一个虚构项目，请先检查已有记忆能力。

**工作方式：**只在首次需要长期连续性时，先检查原生记忆和用户已安装、授权的 provider。把文档声称、安装、启用、可调用和隔离测试分开记录。如果原生能力不覆盖跨 Agent，但一个已安装 provider 通过保存、读取、更正、删除和并发保护测试，才提出 C；否则提出 B 或 D。

**得到什么：**当前选择、数据位置、唯一来源、共享范围、未验证项和用户需要确认的授权。不会自动复制全部历史，也不会因为 Skill 已安装就虚构可用引擎。

## 记忆读取：分清时间、来源和冲突（未发布）

**请求：**根据我已授权的虚构展览记录，确认展板最后放在哪个入口。

**工作方式：**只查这个展览的相关记录。筹备笔记写“打算放东门”，活动记录写“开场时改到南门”，可以是计划与后续结果，不必判成冲突。若另有同一时刻的记录写北门，则核对原始来源，保留未解决分歧；晚录入的摘要不自动更可信。

**边界：**只找到计划就不能声称已经执行；没有结果时说明在已检查的授权来源中未找到，不推出事情从未发生。不为回答这个问题扫描全部历史或新增记忆引擎。

## 生活支持：本人目标与可行帮助（未发布）

下面是另外独立构造的虚构场景，属于使用说明，不是评测输入或实测结果。[生活领域来源核验](RESEARCH-LIFE-2026-10-13.md)和[验证范围](VALIDATION-LIFE.md)分别记录方法依据与实际检查；研究不能证明本 Skill 有效。

| 请求 | 工作方式与边界 |
|---|---|
| “午饭后只有 20 分钟，想把餐桌腾空，下午留给拼图。” | 给一个有范围的整理顺序，以餐桌可用为完成条件；不把整个家列成待办。拼图可以只为乐趣，不要求作品变现、打卡或测人格。 |
| “晚班后准备早餐只有 10 分钟，帮我想一个容易坚持的办法。” | 依据已提供的时间给简单的准备选项，必要时只问会改变选择的食物限制。记录、设备和检查均可选；这是日常习惯帮助，不据此诊断或开个人处方。 |
| “虚构家庭账上有 1800 元，周五到账 1200 元，周三付押金 1000 元，另有 750 元必要支出也须在周五到账前支付，还想买 480 元电饭煲。” | 先按付款日期检查：周五到账前的两笔必要支出共 1750 元，现有余额最多剩 50 元，不能提前算入周五收入；在到账和其他费用确认后重新比较购买。不给固定储蓄比例，也不擅自读取银行账户或下单。 |
| “我在做档案管理，想了解展览运营是否适合我，但暂时不能离职。” | 从当前约束出发，核对岗位职责，再提出一次成本可承受的了解或尝试，例如分析公开的岗位任务。没有测试结果也能继续帮助；不凭兴趣推断人格或替本人决定辞职。 |
| “朋友临时取消散步，我有点失落，先听我说；如果我之后想回复，再帮我写两句。” | 先回应想被听见的需要，不猜测朋友动机，不强制复盘或情绪练习。用户要草稿时再起草；草稿不等于发送授权，私事也不默认写入长期记忆。 |

具体表达和步骤取决于目标、可用上下文及宿主能力；不要求所有请求使用同一格式。
