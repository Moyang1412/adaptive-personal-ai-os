# 不确定结果与反馈：第二批源码/论文取舍

2026-10-17维护候选；本人完成阅读、修改和脚本检查。本轮不新增委托式模型验证，也不声称实际宿主已经安全执行。

## 实际缺口与改动

原workflows要求根据结果继续、避免重复失败，但没有具体说明：修改型请求超时后，动作可能已经成功。新段落要求先通过支持的回执或状态查询核对原请求；把待处理、未知和失败分开。仅在实际服务合同与原授权允许时重放；同一键必须对应同一意图/参数/账号，并仍在去重有效期内。读不到记录不一定等于没有发生，尤其存在查询延迟时。

这适用于获准的预约、工单、文件写入等动作；不是新增这些动作的权限，也不提供跨服务的“恰好一次”执行器。安全的只读重试可以按工具指引继续，不能把所有异常一律变成永久停止，也不能无限循环。

## 实际运行的示例，而非伪装的模型评测

运行：python evals/fixtures/uncertain_action_demo.py。

这是内存中的虚构服务和手写调用者：先完成一条记录但丢失响应。盲目重新创建产生2条；通过回执核对并在支持的同键合同内重放仍是1条；同键换意图被拒绝；删除回执以模拟去重期失效后再次重放则变成2条。

示例确实执行，但“盲目调用者”不是旧智序实际答复；不能说旧版犯了这个错误、新版模型已经治好。它不测试真实网络、跨进程持久化或并发，只展示新规则针对的机制。另加4个独立规范用例，路由结构检查由118变122；结构通过也不是模型行为通过。

## 学习/复盘论文：不强行增加核心规则

- [Huang等，ICLR2024](https://arxiv.org/pdf/2310.01798)：核对内部自纠正的定义、对比成本、反馈和局限段落；实验模型/任务有特定范围，不推出2026年所有模型都不能自纠正。
- [Reflexion，v4](https://arxiv.org/html/2303.11366v4)：核对Actor/Evaluator/反馈记忆过程和局限；不同任务用了不同评价信号。它不是单纯“多反思几遍就变强”，也不是在本产品中训练了模型权重。
- [ProCo，v2](https://arxiv.org/html/2405.14092v2)：该版本标题为Large Language Models Can Self-Correct with Minimal Effort；核对遮蔽关键条件、逆向验证和纠正设计。其正面结果提醒我们不能把较早论文当普遍否定，但不能据此给所有生活问答添加反复调用或把自洽当事实核验。

三者的任务、反馈与比较条件不同。智序现有“优先用实际结果/来源反馈，自己重复同意不等于正确”的规则仍适用，本轮没有为凑论文数量而追加一个通用自反思循环。需要未来以匹配成本和具体失败验证适用性，不能宣传已获得论文里的提升。
