# Feedback log

这里记录会影响公共 Skill 行为的可复用反馈。一次性的个人偏好、私有项目细节和真实用户数据不应写入这里。

## 记录模板

```markdown
### YYYY-MM-DD — <简短标题>

- 来源：用户纠正 / 失败任务 / 测试回归 / 重复澄清 / 工具限制
- 案例：<routing case ID，或说明没有现有案例>
- 观察到的行为：<只写可验证事实>
- 分类：上下文缺失 / 路由错误 / 规则错误 / 执行错误 / 验证不足 / 工具限制
- 候选改进：<一条最小规则或文档改动>
- 适用范围：全局 / 某个模式 / 某个项目 / 一次性实验
- 可能副作用：<新增误触发、额外提问、变慢等>
- 验证任务：<如何验证候选改进>
- 结果：待验证 / 保留为实验 / 升级为公共规则 / 关闭
- 证据：<测试命令、案例结果或 issue/PR 链接>
```

## 升级规则

候选改进默认留在实验或项目范围。只有用户明确要求、同类问题至少重复两次，或评测显示它是明显的跨项目规律时，才升级 `SKILL.md`。每次升级都要更新 `CHANGELOG.md`，并在对应案例中留下可复现的验证证据。
